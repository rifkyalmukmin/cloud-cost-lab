# data/mock/ — Demo Dataset

Synthetic billing, resource, and utilization data for demo mode (`DEMO_MODE=true`).

**Status: Phase 1 IMPLEMENTED.** These JSON files are consumed by `MockBillingProvider` / `MockUsageProvider` in `apps/api` and are loaded into PostgreSQL by `python -m costlab.seed` (or automatically at container start).

## Files

```text
projects.json    4 GCP-style projects (production / staging / development / legacy sandbox)
services.json    4 services: Compute Engine, Cloud SQL, Cloud Storage, Artifact Registry
resources.json   12 resources: VMs, Cloud SQL, storage buckets, one Artifact Registry
cost.json        1,164 daily cost records (2026-06-01 → 2026-09-05), rising trend,
                 a Compute +35% spike week (Aug 10–16), a September budget-risk run-rate
usage.json       1,164 daily utilization samples (CPU/memory/disk/network/requests)
```

`recommendations.json` and `forecast.json` will be added in their phases (4 and 6).

## Determinism

- Generated by `scripts/generate_mock_data.py` with fixed seeds (`COST_SEED=42`, `USAGE_SEED=43`) — **no wall-clock, no per-request randomness**.
- Re-running the generator is byte-identical unless the generator logic changed; the files are committed so demos and tests always see the same data (ADR-003).
- Regenerate only when intentionally changing scenarios, and review the diff.

## Scenarios baked in

Idle VM (`vm-report-dev-1`), oversized VM (`vm-etl-staging-1`), underutilized Cloud SQL (`sql-shop-orders-staging`), unallocated cost (`cc-lab-legacy-sandbox`, no ownership labels), unexpected Compute spike (week of 2026-08-10), budget-risk September run-rate, dev-VM weekend dip.

## Design intent

- Data is **realistic but obviously synthetic** (no real project IDs; plausible prices only).
- Dataset exercises the demo scenarios Phase 4+ detection rules will need; full scenario list: [`docs/cost-model.md`](../../docs/cost-model.md).
